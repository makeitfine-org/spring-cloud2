# Plan: Fast Tests (Embedded Kafka + H2) + IT Phase Split

## Context

Current tests (`*IntegrationTest.java`) use Testcontainers (Docker: PostgreSQL + Kafka) and run on every `mvn test` call, making them slow. The goal is to:

1. Create fast tests using **embedded Kafka** + **H2 in-memory database** — no Docker needed, run in `mvn test` (Surefire)
2. Rename existing Testcontainer tests to `*IT.java` so they run in `mvn integration-test` (Failsafe) via `mvn verify`

## Step 1: Root pom.xml — Maven Plugins

Add after the `maven-checkstyle-plugin` block in `<build><plugins>`:

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <configuration>
        <excludes>
            <exclude>**/*IT.java</exclude>
        </excludes>
    </configuration>
</plugin>
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-failsafe-plugin</artifactId>
    <configuration>
        <includes>
            <include>**/*IT.java</include>
        </includes>
    </configuration>
    <executions>
        <execution>
            <goals>
                <goal>integration-test</goal>
                <goal>verify</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

Spring Boot parent BOM manages Surefire and Failsafe versions — no `<version>` needed.

## Step 3: H2 Schema Files

`BIGSERIAL` is PostgreSQL-only; H2 uses `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
`ON CONFLICT DO NOTHING` works in H2 2.x with `MODE=PostgreSQL` (set in R2DBC URL).

### `order-service/src/test/resources/schema-h2.sql`
```sql
CREATE TABLE IF NOT EXISTS orders (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id VARCHAR(255) NOT NULL,
    quantity INTEGER NOT NULL,
    price DECIMAL(10, 2),
    status VARCHAR(50) NOT NULL DEFAULT 'PENDING',
    failure_reason VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### `inventory-service/src/test/resources/schema-h2.sql`
```sql
CREATE TABLE IF NOT EXISTS inventory_items (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id VARCHAR(255) NOT NULL UNIQUE,
    quantity INTEGER NOT NULL DEFAULT 0,
    reserved_quantity INTEGER NOT NULL DEFAULT 0
);
INSERT INTO inventory_items (product_id, quantity, reserved_quantity)
VALUES ('prod-1', 100, 0), ('prod-2', 50, 0), ('prod-3', 200, 0)
ON CONFLICT (product_id) DO NOTHING;
```

### `delivery-service/src/test/resources/schema-h2.sql`
```sql
CREATE TABLE IF NOT EXISTS deliveries (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_id BIGINT NOT NULL,
    product_id VARCHAR(255) NOT NULL,
    quantity INTEGER NOT NULL,
    status VARCHAR(50) NOT NULL DEFAULT 'SCHEDULED',
    address VARCHAR(500),
    scheduled_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    delivered_at TIMESTAMP
);
```

## Step 4: application-fast.yml (per service)

Each service gets `src/test/resources/application-fast.yml`. DB name differs per service.

Key settings:
- `r2dbc.url`: H2 in-memory with PostgreSQL mode + DB_CLOSE_DELAY=-1 (keeps DB alive across R2DBC pool connections)
- `spring.main.allow-bean-definition-overriding: true` — needed so the `@TestConfiguration` can override `DatabaseConfig.initializer` bean (which hardcodes `schema.sql`)

```yaml
# order-service: r2dbc:h2:mem:///orderdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
# inventory-service: r2dbc:h2:mem:///inventorydb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
# delivery-service: r2dbc:h2:mem:///deliverydb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1

spring:
  main:
    allow-bean-definition-overriding: true
  r2dbc:
    url: r2dbc:h2:mem:///orderdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
    username: sa
    password:
  sql:
    init:
      mode: always

eureka:
  client:
    enabled: false

management:
  tracing:
    enabled: false
```

**Why `allow-bean-definition-overriding`:** `DatabaseConfig.initializer` hardcodes `schema.sql`. The fast test's nested `@TestConfiguration` redefines the same bean name `"initializer"` to load `schema-h2.sql`. Without override enabled, Spring throws a conflict error. With it, the test bean wins and only H2 schema runs.

## Step 5: Fast Test Classes

### Key annotations on all 3 fast test classes:
```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
@ActiveProfiles("fast")
@AutoConfigureWebTestClient
@EmbeddedKafka(
    partitions = 1,
    bootstrapServersProperty = "spring.kafka.bootstrap-servers",
    topics = {"order-created", "inventory-reserved", "inventory-failed", "delivery-scheduled"}
)
```

`bootstrapServersProperty = "spring.kafka.bootstrap-servers"` sets the property that `KafkaConfig` reads via `@Value`, wiring all producer/consumer beans to the embedded broker automatically.

### `@TestConfiguration` in each test class (overrides `DatabaseConfig.initializer`):
```java
@TestConfiguration
static class H2SchemaConfig {
    @Bean("initializer")
    ConnectionFactoryInitializer initializer(ConnectionFactory connectionFactory) {
        ConnectionFactoryInitializer init = new ConnectionFactoryInitializer();
        init.setConnectionFactory(connectionFactory);
        init.setDatabasePopulator(
            new ResourceDatabasePopulator(new ClassPathResource("schema-h2.sql")));
        return init;
    }
}
```

### `@BeforeEach` setup pattern:
```java
// For order and delivery services:
repository.deleteAll().block();

// For inventory service — use DatabaseClient (avoids InventoryItem constructor uncertainty):
databaseClient.sql("DELETE FROM inventory_items").fetch().rowsUpdated().block();
databaseClient.sql("""
    INSERT INTO inventory_items (product_id, quantity, reserved_quantity)
    VALUES ('prod-1', 100, 0), ('prod-2', 50, 0), ('prod-3', 200, 0)""")
    .fetch().rowsUpdated().block();

// For all: create KafkaConsumer and KafkaProducer using KafkaTestUtils:
Map<String, Object> consumerProps = KafkaTestUtils.consumerProps(
    "test-group-" + System.nanoTime(), "true", embeddedKafkaBroker);
consumerProps.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");
kafkaConsumer = new KafkaConsumer<>(consumerProps, new StringDeserializer(), new StringDeserializer());

Map<String, Object> producerProps = KafkaTestUtils.producerProps(embeddedKafkaBroker);
kafkaProducer = new KafkaProducer<>(producerProps, new StringSerializer(), new StringSerializer());
```
